# DV LSFG 0.4.6（实验版）

0.4.6 将 FSR 选择器从左到右排列为：关闭、性能、平衡、质量、超高质量。
配置值和渲染比例的含义保持不变，旧配置无需迁移。

0.4.5 支持帧生成模型与光流质量实时切换。在已加载的插帧层上点击游戏“应用”
或 UMM“保存设置”，倍率、模型和光流质量均无需重启；DLL 路径修改仍需重启。

0.4.4 将 LSFG 状态、模型/质量的重启要求和 FSR 渲染/输出信息移到原生底部简介。
悬浮各项设置可查看说明；移除了只读状态按钮和 FSR 即时生效提示。

0.4.3 支持倍率实时切换：在已加载的插帧层上应用 2×/3×/4×，无需重启游戏。
切换时可能短暂停顿；模型、光流质量和 DLL 路径仍需重启。

0.4.2 将 FSR 锐化改为原生滑动条：0%–100%，1% 步进，拖动时显示当前百分比，
沿用游戏“应用/放弃”按钮。

0.4.1 修复开启 FSR 后每半秒出现长帧：稳定游戏期间不再全局扫描 Unity 对象，
改由相机创建事件注册；隐藏的设置面板也停止周期刷新。FSR/LSFG 设置保持原样。

## 新增 FSR 1.0 超分辨率

在游戏“设置 → 图形质量”选择“FSR 1.0 超分辨率”，点击原生“应用”即可生效，
无需重启。提供关闭、超高质量、质量、平衡、性能及 0–100% 锐化；0% 不执行锐化。
默认关闭，建议先试质量或超高质量、20% 锐化。屏幕分辨率继续表示输出分辨率，
场景按所选比例降低渲染分辨率，菜单、HUD 和快捷栏的屏幕叠加 UI 保持输出分辨率。
状态行显示实际渲染尺寸与输出尺寸；主菜单没有游戏场景相机时显示等待相机。

FSR 与 LSFG 开关独立，FSR 本身不需要 Lossless.dll。先执行场景抗锯齿/后处理、
FSR EASU/RCAS 和屏幕 UI，再交给现有 LSFG 插帧。FSR 不替代游戏抗锯齿；
低比例可能增加铁轨、植被和仪表细节闪烁。CPU 受限场景不保证帧率提高，
LSFG 仍按输出分辨率运行。当前仅支持非 VR、主显示器、全屏场景相机，
前向和延迟渲染均有接入；雨水/所有后处理组合仍需进一步场景测试。

UMM 停用模组或关闭 FSR 时恢复原相机目标。分辨率/质量切换重新建立目标，
GPU 初始化失败会报告错误并回退；修改模式或分辨率后可重试。保留用户原有
插帧配置，新增 FSR 配置键为 `FsrMode` 与 `FsrSharpness`。

独立的 Windows x64 / Unity Mod Manager 模组，前置为已部署 DXVK 的 DVVulkan。
DVVulkan 提供 D3D11 → Vulkan；DVLSFG 的原生 Vulkan 层负责 LSFG 3.1 帧生成。
DVLSFG 不修改或包含 DVVulkan，也不修改系统 Vulkan 注册表。

## 安装和启动

1. 退出游戏，把 DVLSFG-0.4.2.zip 拖入 UMM 安装。
2. 确保 DVVulkan 已启用且完成退出后的 DXVK 部署。
3. 普通启动游戏，在 UMM 启用 DVLSFG，填写自己安装的 `Lossless.dll` 完整路径并保存。
   打开游戏“设置 → 图形质量”，将“LSFG 帧生成”设为开启，点击原生“应用”。
4. 点击“检查 DLL 兼容性”。查看 `Mods/DVLSFG/probe.log`，必须显示 `Probe passed`。
5. 首次启用后正常退出游戏，等待自动部署完成，再从 Steam 或原有快捷方式照常启动。

不再需要专用脚本启动。UMM 会自动部署游戏目录专用的 `vulkan-1.dll` 引导组件，
在第一次 Vulkan 调用前读取插帧开关和 UMM 状态，并转发到 Windows 系统 Vulkan。
首次安装需要重启一次；之后可以正常从 Steam 或原有游戏快捷方式启动。
组件仅为游戏进程设置图形层环境，不修改系统注册表、系统 DLL 或 Steam 启动项。
已有第三方 `vulkan-1.dll` 会被保留，并在 UMM 报告冲突。DVVulkan 的 `d3d11.dll` 和
`dxgi.dll` 保持原样；引导器会检查它们与已安装前置的文件一致。

## 设置与实际状态

0.4.2 修复开启插帧时切换分辨率卡住的问题：正确恢复过期交换链、清理生成任务，
并处理过期呈现路径上未完成的应用围栏。分辨率变更无需额外重启；资源重建时会
有短暂暂停。倍率、模型及光流质量均可实时切换。

安装并启用 UMM 模组后，普通启动就会在游戏原生“设置 → 图形质量”顶部显示 LSFG
开关、倍率、模型和光流质量。它们使用游戏原生选择器和“应用/放弃”按钮；未应用
的修改也参与原生的离开确认。面板支持滚动，以保留全部原有图形选项。
预设保持固定，滚动内容与预设之间沿用“高级选项”的分隔条样式。
UMM 启用状态和插帧开关独立；停用模组会暂停插帧并隐藏新选项，重新启用不会
覆盖已保存的插帧开关。DLL 路径和兼容性诊断保留在 UMM。

引导组件在普通启动时自动接入。已经初始化的插帧可即时暂停/恢复，倍率在点击
原生“应用”（或 UMM“保存设置”）后生效，模型及光流质量也支持同样的实时切换。
切换时等待 GPU 完成，重建资源并清空历史，可能短暂停顿；
若本次未加载插帧层，界面显示“需重启以启用”，不再要求 LSFG 启动方式。

- 支持 2×、3×、4×，标准/性能模型，光流比例 0.25–1。
- 倍率、标准/性能模型及光流比例均可实时切换；DLL 路径修改仍需重启。
- 已初始化的插帧可通过 UMM 开关暂停/恢复；恢复时重新准备历史输入。
- 设置页显示原生层是否实际加载、原生状态、已处理真实帧及生成帧计数。
  “已处理真实帧”只计入参与插帧并成功呈现的输入帧；暂停时不增长。
- 如果原生层未加载、DLL 不兼容或交换链不受支持，不能将 UMM 的启用状态当作插帧生效。
- 原生状态和兼容性检查的技术诊断保持英文；UMM 界面随游戏中文/英文语言切换。
- 设置页显示输入/提交帧率和含同步等待的呈现处理时间，另保存到 `metrics.ini`。
  提交帧率不代表显示器实测刷新率，处理时间也不是输入延迟测量。
- “保存输入 / 生成帧对照图”把一组 BMP 存入 `captures`，可用于检查画面。
  截图会短时增加 GPU 同步和磁盘开销，建议仅在诊断时使用。

## 支持范围和限制

0.4.2 不再强制 FIFO / 垂直同步。启用插帧时使用 IMMEDIATE 呈现；不支持该模式的
显示表面会报告不可用并回退原始呈现。游戏原生帧率设置继续控制输入帧率，生成器
尝试按 2/3/4 倍提交。高精度调度把输出分散到各个时间点；无上限时参考实际处理
开销，并排除自身等待以避免帧率逐渐下降。
GPU、CPU 与同步处理开销仍可能降低原始帧率。IMMEDIATE 允许超过刷新率提交，
也可能撕裂；屏幕无法完整显示超过其刷新率的所有帧。
RTSS 在本机仍报告游戏原始 Vulkan 调用频率；mod 的提交数不等于 RTSS 或屏幕
显示帧率。实际行车的流畅度和显示帧间隔仍未完成验证。

当前目标是非 VR、SDR、单个游戏 Vulkan 实例/渲染设备，8 位 RGBA/BGRA 单层交换链。
多交换链同时呈现、部分复杂呈现扩展组合及其他格式回退到普通呈现。
不提供缩放功能，不支持 HDR、双 GPU 分担或 VR 帧生成。
只增加显示帧，游戏模拟、网络及输入更新频率不变。

这是同步呈现的移植原型，会等待 GPU 完成后再复用资源。
行车中的基础帧率、输入延迟、画质、帧间隔及其他模组的兼容性仍需进一步实测；
不能用插帧计数推断真实显示刷新率或性能提升。

## 验证情况

已在 NVIDIA RTX 3070 Ti 上用隐藏窗口 Vulkan 测试程序验证真实插帧、精确帧数、
禁用回退及资源销毁；标准 2×：12 输入帧产生 12 生成帧；性能 4×：12 输入帧产生
36 生成帧。两条路径 Vulkan 校验零错误，正常退出。
标准 2× 也通过了本机现有自动 Vulkan 覆盖层一起加载的测试。
暂停两帧后恢复、运行中重建交换链的检查也通过，计数正确且 Vulkan 校验零错误。
组合呈现模式/ID/围栏元数据、额外 Vulkan 设备创建与销毁也通过检查。
读回像素验证了生成图像是中间帧：标准 2× 测试的前后输入红色值 43/64，生成值 53。

Derail Valley 主菜单实测：UMM 0.32.4 与 DVVulkan 1.0.1 加载独立模组，1920×1080
标准 2× 长时间运行累计约 69 万真实帧和 69 万生成帧，正常退出。
最后一秒输入/提交速率约 82.5/165 FPS，仅为提交统计；静态菜单截图未见明显损坏。
验证使用 Vulkan 校验层 1.4.363；旧版 1.4.309 无法正确校验本机 DXVK 的新扩展。
尚未验证实际行车、VR、HDR 或端到端输入延迟，菜单测试不能替代这些验证。
最终同步修复版本另完成 4,872 对主菜单帧，完整同步/线程校验无错误，正常退出。
详细验证范围与测试环境隔离说明见 `VALIDATION.md`。

资源兼容性：测试过的 `Lossless.dll` 文件版本 3.2.2.0 可转换全部 52 个 LSFG 3.1
着色器映射；文件版本 3.0.0.1 的测试文件缺少所需资源，拒绝启用。
文件版本本身不能替代资源检查。模组包不附带 Lossless.dll 或提取出的着色器。

## 恢复与卸载

启动问题：在游戏设置关闭插帧并重启，或使用 `Launch-Without-LSFG.cmd` 临时绕过
插帧（保留现有 DXVK）。恢复启动可在配置损坏时使用。
检查 `bootstrap.log`、`deployment.log`、`probe.log` 和本次启动的 `native.log`。
卸载：先在 UMM 停用 DVLSFG，退出游戏等待自动移除引导组件，再删除模组。
仅移除本模组拥有的游戏目录 `vulkan-1.dll` 和所有权标记，不修改其他图形 DLL。
如果直接删除模组目录，残留引导组件会因模组文件缺失而转发普通 Vulkan，不加载插帧。
DVVulkan 的停用/卸载仍由其自身流程处理。
